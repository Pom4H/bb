# Handoff: офисный доступ к Pom4H/bb

Дата: 5 ноября 2026. Репозиторий: `Pom4H/bb`. PR: [#1](https://github.com/Pom4H/bb/pull/1). Ветка: `feat/office-access-gateway`.

## Состояние передачи

**Gateway реализован и проверен отдельно. Полноценная многопользовательская авторизация bb и вход официального мобильного клиента ещё не завершены. PR должен оставаться draft; это не разрешение на офисное production-развёртывание.**

Исходный head PR: `da45153b4280f6558355aefceb86cd7fa7b67b08`. Base: `fa30b0a7dcdf745f7baf8e41721f754b7d3198fe`. Продолжать ту же ветку, не переносить работу напрямую в `main`. Перед записью сверить актуальный head, не использовать force push.

Пользователь хочет расширять готовый bb, переиспользуя форки и плагины. Не писать заново OIDC, мобильный клиент или агентную оболочку без проверки существующей реализации. Bun не является основанием для переписывания bb или этой задачи.

## Что уже сделано

Предыдущий незагруженный follow-up применён к проверенному исходному коду. Добавлены мобильная браузерная форма входа, безопасный возврат на исходную страницу, отзыв предыдущей сессии при смене пользователя, закрытие связанных соединений и сохранение upstream WebSocket 401/403 вместо ошибочного 502.

Дополнительное усиление:

- `audit.mjs`: асинхронный callback аудита не принимается за успешную запись. Возвращённый Promise приводит к отказу; его отклонение обрабатывается. Это намеренно синхронный контракт, не обещание доставки внешнему хранилищу логов.
- Логи содержат категорию маршрута, например `/api/v1/threads/*`, а не произвольный путь с идентификатором или токеном приглашения. Неизвестные/невалидные пути: `/other`, `/invalid-path`. Идентификатор пользователя остаётся для атрибуции и требует политики хранения.
- Дополнительные регрессии: асинхронный аудит, секреты в URL, дублированные security headers, отдельные HEAD-разрешения, лимит сессий одного пользователя и отсутствие обхода через мобильные заголовки.
- `verify.mjs`: переносимый запуск синтаксической проверки, всех тестов и валидации примера policy, без shell wildcard и дополнительных npm-зависимостей.
- `smoke.mjs`: девять read-only HTTP-проверок развёрнутого gateway. Ключ читается из закрытого файла, не из argv; редиректы не выполняются. Проверяются статусы и JSON, а не просто HTTP 200.

Основные файлы: `extensions/office-access/{gateway,login,audit,policy,smoke,verify}.mjs`, `server.ts`, `test/*.test.mjs`. Инструкции: `README.md`, `skills/office-access/SKILL.md`, `docs/office-access.md` и исторический `docs/office-access-follow-up.md`.

Подготовка на машине с сетью, без автоматического применения:

Последняя команда — диагностика совместимости, не обещание чистого применения. Diff исключает сгенерированные миграции и lockfile только для ревью. При реальном переносе их требуется корректно регенерировать инструментами репозитория.

| Группа донора | Что переносить/проверять |
| --- | --- |

Донор не обещает изоляцию машин и provider credentials. Его описание тестов — отчёт автора; в этом сеансе они не запускались. Портировать исходники с сохранением лицензии/атрибуции. Не принимать прототип за прошедший независимый security audit.

В ранее прочитанном README bb-lite все участники могут читать все потоки: не заменять этим требование приватности отделов и не мигрировать проект автоматически.

## Дальнейшие задачи в порядке исполнения

### P0 — права на данные, до общего офисного сервера

Перенести и адаптировать Authentik-срез, не писать второй OIDC рядом. Решить один источник идентичности: текущий gateway удаляет внешний Authorization и свою cookie, поэтому OIDC-cookie/identity донора нельзя считать уже связанными с ним. При соединении слоёв сервер должен проверять доверенный канал и пользователя, а не принимать произвольный `x-bb-office-subject` с открытого порта.

Проверить HTTP, CLI, SDK, REST/RPC, realtime, терминалы, файлы, списки и поиск. Не раздавать всем сотрудникам admin ради совместимости интерфейса. Общий `/ws`, плагины, shell и настройки сейчас сознательно ограничены.

Критерий: два разных пользователя получают только разрешённые потоки/файлы/события; viewer не отправляет и не меняет; outsider не узнаёт приватный объект; отзыв прав прекращает чтение без переподключения; одноразовый invite не принимается дважды при гонке.

### P1 — официальный мобильный клиент, без новой оболочки

Существующее приложение находится в `apps/mobile`. Подтверждённая точка сбоя: `src/lib/profiles/probe.ts` сначала запрашивает `/health` и `/api/v1/system/config` без gateway-сессии. `src/screens/settings/AddServerScreen.tsx` при любой ошибке завершает подключение; WebView входа ещё не открыт.

Продолжение: различить 401 (нужен вход), 403 (нет прав), сетевую ошибку и неверный формат; добавить проверенный auth-переход к тому же серверу; затем повторить probe. Обеспечить единую сессию для native fetch/SDK, native WebSocket и WKWebView/Android WebView. Использовать существующие `src/lib/native`, `src/lib/session`, `src/lib/connection` и `screens/webview`, не хранить ключи в localStorage, URL, сообщениях агента или произвольных заголовках сторонних сайтов.

Не считать iOS/Safari cookie автоматически общей с native fetch. Ограничить перенос credentials точным origin, очистить обе cookie-среды и per-profile query cache при logout/смене пользователя. Deep link должен сохраняться через вход; файл должен скачиваться с авторизацией в WebView. После релонча, expiry, отзыва роли и потери сети не должно быть тихого возврата в owner.

Push требует отдельной проверки владельца устройства и получателя. Не включать приватные тексты в уведомления, пока эти проверки не подтверждены. В текущем PR native вход и push ACL не реализованы.

### P2 — изоляция исполнения и эксплуатация

Процессы агента не должны иметь обходной доступ к core loopback, policy, ключам и данным других пользователей. Ограничить доступ к регистрации плагинов/машин. Привязать фоновые действия к подтверждённому инициатору; значения userId от модели не доверенные.

Передать оператору TLS, rate limits на ingress, ограничения загрузок, резервные копии и retention аудита. Проверить отсутствие альтернативного bb connect/tunnel/port share в обход выбранной границы. Плагины bb остаются full-trust, gateway не делает их sandboxed.

## Команды проверок

Из корня:

```sh
node extensions/office-access/verify.mjs
git diff --check
```

На машине с полным checkout и установленными зависимостями:

```sh
pnpm install --frozen-lockfile
pnpm exec turbo run build typecheck test --filter=@bb/server --filter=@bb/app --filter=@bb/mobile
```

Расширение вне pnpm workspace: отдельно выполнить `verify.mjs`, установить его через `bb plugin install <absolute-path>/extensions/office-access`, настроить private policy и проверить status/check/reload внутри настоящего bb. Не использовать тестовый фасад как замену этой проверке.

Read-only staging smoke:

```sh
node extensions/office-access/smoke.mjs https://bb.example.com /absolute/private/path/operator-key
```

Требуется plaintext key оператора в обычном закрытом файле, не весь policy JSON. Скрипт не записывает бизнес-данные, не следует редиректам и не проверяет WebSocket/native/row ACL. Не запускать его с ключом из аргументов командной строки или опубликованного файла.

CI запускать вручную по согласованному проектному процессу; этот handoff не добавляет auto-run workflow. Не маркировать PR ready, не сливать и не разворачивать автоматически.

## Условия завершения

Все P0/P1 сценарии должны пройти на целевой сборке bb; iOS и Android — на реальных устройствах либо явно помеченных проверочных сборках с последующим device acceptance. Нужны отчёт о миграции, негативные тесты доступа, проверка logout/revocation, изоляции данных и исполнения. Только после этого пересматривать draft/готовность.

Для возврата во время пилота сначала закрыть публичный ingress. Удаление gateway не должно открывать core. Эта доработка сама не меняет БД; после последующего переноса Authentik откат необходимо планировать с резервной копией и реальными миграциями, а не только возвратом контейнера.
